# Task 6 — Schema delle lezioni e test di validità dei contenuti

Target: claude

## Goal
Primo passo della feature `aggiunta-materiale-lezione`: definire con zod lo
schema del file di lezione, da cui derivano i tipi TypeScript usati dall'app,
e il test di validità che passa ogni file di `contenuti/lezioni/` allo schema
e ai vincoli tra file. Il test fa parte di `npm test`, quindi un file
malformato blocca la pubblicazione e non arriva mai nell'app.

## Acceptance criteria
- `zod` è una dipendenza di sviluppo; l'app importa da `src/contenuti/schema.ts`
  solo tipi (`import type`), mai valori zod.
- Lo schema descrive la lezione (`id`, `title`, `sentences`, `vocabulary`,
  `grammar`) e i suoi elementi esattamente come il documento di feature
  § Data and state: frasi con `id`, `it`, `en`, `alternatives`; vocaboli con
  `id`, `it`, `en` (almeno una traduzione); schede con `id`, `title`, `body`.
  Tutti i testi sono non vuoti e senza spazi iniziali o finali; almeno una
  delle tre liste è non vuota; chiavi sconosciute sono rifiutate.
- I tipi `Lezione`, `Frase`, `Vocabolo`, `Scheda` sono esportati e derivati
  dallo schema con `z.infer`.
- Una funzione pura in `src/contenuti/validazione.ts` riceve i file della
  cartella (nome e contenuto) e restituisce gli errori, ognuno con il file e
  l'elemento colpevoli, per ogni caso elencato in § Interfaces and contracts,
  Test di validità: schema non rispettato; nome del file diverso dall'`id` o
  `id` non nella forma `NN-argomento`; due lezioni con lo stesso `NN`; id di
  elemento malformato per il suo tipo (`fNN`, `vNN`, `gNN`) o ripetuto nella
  lezione; stessa frase italiana o stesso vocabolo italiano due volte, anche
  in lezioni diverse, confrontando senza maiuscole, spazi superflui e
  punteggiatura finale; `en` di una frase ripetuta fra le `alternatives` o
  traduzione ripetuta in un vocabolo; file non JSON nella cartella.
- `tests/validazione.test.ts` copre ogni caso d'errore sopra e un insieme di
  lezioni valido, con dati finti.
- `tests/contenuti.test.ts` legge i file reali di `contenuti/lezioni/` e
  fallisce, con il messaggio della funzione, se la validazione restituisce
  errori. Una cartella vuota o assente passa.
- `npm test`, `npm run typecheck` e `npm run build` riescono.

## Decisions
- **Cartella assente = cartella vuota**: git non versiona cartelle vuote, e un
  `.gitkeep` sarebbe un file non JSON che il test rifiuta. Il documento dice
  che la cartella vuota è valida e non fissa il caso della cartella assente.
- **Vincoli tra file in una funzione pura separata dal test dei file reali**:
  così ogni caso d'errore si prova con dati finti, mentre il test sui file
  reali resta una sola asserzione.
- Percorsi `src/contenuti/` e `tests/`: il documento non li fissa; seguono la
  struttura del task 1.
- Settled here (`.claude/domain/features/aggiunta-materiale-lezione.md`
  § Interfaces and contracts, Test di validità): la cartella assente vale
  come vuota. Nessun passaggio del documento va cambiato.
