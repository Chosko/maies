# Task 4 — Pubblicazione automatica su GitHub Pages

Target: claude+human

## Goal
Quarto passo della feature `scheletro-e-pubblicazione`: la GitHub Action che,
a ogni push su `main`, installa le dipendenze, esegue controllo dei tipi e
test, compila e pubblica il sito su GitHub Pages, più la configurazione di
Pages nelle impostazioni del repository che solo l'utente può fare, perché il
sito sia servito su `maies.chosko.com`.

## Acceptance criteria
- Un workflow in `.github/workflows/` che parte solo sui push a `main` (non
  su pull request né su altri branch) e, in ordine: installa Node e le
  dipendenze con `npm ci`, esegue `npm run typecheck`, `npm test` e
  `npm run build`, carica `dist/` e pubblica con le azioni ufficiali di
  GitHub per Pages (configurazione, caricamento, pubblicazione).
- Se un passo fallisce, la pubblicazione non avviene e resta online la
  versione precedente: la pubblicazione è un job che dipende dalla
  compilazione riuscita.
- Il workflow ha i permessi minimi richiesti da Pages (`pages: write`,
  `id-token: write`, `contents: read`) e un gruppo di concorrenza che non
  interrompe una pubblicazione in corso.
- Le impostazioni Pages del repository hanno sorgente "GitHub Actions",
  dominio personalizzato `maies.chosko.com` e "Enforce HTTPS" attivo,
  verificate come indicato sotto.

## Decisions
- **La pubblicazione reale si verifica quando il lavoro arriva su `main`**:
  il task si sviluppa su un branch di lavoro, quindi la sua chiusura richiede
  il workflow valido e le impostazioni Pages verificate, non un sito già
  pubblicato. La prima pubblicazione avviene al merge su `main`.
- Il file `CNAME` alla radice resta com'è: GitHub lo ignora con la
  pubblicazione tramite Action.

## Manual interventions

⚠ REQUIRES MANUAL INTERVENTION — interrompi l'implementazione in questo punto
e guida l'utente nelle impostazioni del repository su GitHub; aspetta la sua
conferma e verifica l'esito prima di proseguire:

1. Dopo che il workflow è scritto e i comandi `typecheck`, `test` e `build`
   riescono in locale: in GitHub, Settings → Pages del repository
   `Chosko/maies`, impostare **Source: GitHub Actions**, **Custom domain:
   `maies.chosko.com`** (Save) e, appena il certificato è pronto, spuntare
   **Enforce HTTPS**. Verificare con `gh api repos/Chosko/maies/pages` che
   `build_type` sia `workflow`, `cname` sia `maies.chosko.com` e
   `https_enforced` sia `true`; se il certificato non è ancora emesso,
   annotarlo nel report come unico punto rimasto all'utente.
