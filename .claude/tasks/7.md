# Task 7 — Catalogo dei contenuti in sola lettura

Target: claude

## Goal
Secondo passo della feature `aggiunta-materiale-lezione`: il catalogo che
carica alla compilazione tutti i file di `contenuti/lezioni/` e li espone in
sola lettura, con gli identificatori globali già calcolati. Esercizi,
vocaboli, dizionario, grammatica e ripetizione degli errori leggono i
contenuti solo da qui.

## Acceptance criteria
- `src/contenuti/catalogo.ts` carica i file con l'importazione statica di Vite
  (`import.meta.glob` con `eager`) e non li valida a tempo di esecuzione.
- Una funzione pura costruisce il catalogo dai moduli caricati; il catalogo
  dell'app è il risultato di quella funzione sui file reali.
- Il catalogo espone, come descritto nel documento di feature § Interfaces
  and contracts, Catalogo dei contenuti: le lezioni in ordine di id; una
  lezione per id o nessuna; tutte le frasi e tutti i vocaboli, ognuno con il
  proprio id globale `<id-lezione>/<id-elemento>` e l'id della lezione; la
  ricerca di una frase o di un vocabolo per id globale, che per un id
  sconosciuto restituisce "nessuno" e non un errore.
- I dati esposti sono in sola lettura: tipi `readonly` e oggetti congelati.
- Con zero lezioni ogni lista è vuota e ogni ricerca restituisce "nessuno".
- `tests/catalogo.test.ts` copre con lezioni finte: l'ordine delle lezioni,
  il calcolo degli id globali, la ricerca per id (esistente, sconosciuto,
  di un tipo sbagliato), la lezione per id e il caso con zero lezioni.
- `npm test`, `npm run typecheck` e `npm run build` riescono.

## Decisions
- **Il catalogo si costruisce con una funzione pura sui moduli**, separata
  dal caricamento con `import.meta.glob`: così si testa con lezioni finte
  senza dipendere dai file reali del repository.
- La ricerca per id globale è separata per frasi e vocaboli: un id di frase
  passato alla ricerca dei vocaboli dà "nessuno".
- I tipi vengono da `src/contenuti/schema.ts` (task 6) con `import type`, così
  zod non entra nel bundle dell'app.
