# Task 1 — Creare il progetto Vue con router e schermate segnaposto

Target: claude

## Goal
Primo passo della feature `scheletro-e-pubblicazione`: creare il progetto
Vue 3 + Vite + TypeScript con Vue Router in modalità hash, Vitest con Vue Test
Utils in jsdom, i comandi del progetto e le quattro schermate segnaposto
raggiungibili dai loro indirizzi. È il contenitore su cui tutte le altre
funzionalità aggiungono il proprio contenuto.

## Acceptance criteria
- Il progetto usa TypeScript, Vue 3 (Composition API, single-file components),
  Vue Router, Vite e il plugin Vue di Vite; `vue-tsc`, `vitest`,
  `@vue/test-utils` e `jsdom` sono dipendenze di sviluppo.
- `package.json` espone comandi separati: `dev` (server di Vite), `test`
  (Vitest in esecuzione singola, non in watch), `typecheck` (`vue-tsc
  --noEmit`) e `build`; ognuno esce con codice non nullo se fallisce.
- La compilazione è servita alla radice `/` (`base: '/'`), non sotto il nome
  del repository.
- Il router usa la cronologia hash e registra `#/esercizi`, `#/vocaboli`,
  `#/dizionario`, `#/grammatica`; `#/` e ogni indirizzo sconosciuto portano a
  `#/esercizi`.
- Ogni schermata segnaposto è un componente a sé e mostra il proprio titolo
  (Esercizi di traduzione, Allenamento vocaboli, Dizionario dei vocaboli,
  Schede di grammatica) e un'indicazione che il contenuto è in arrivo.
- Il componente radice contiene lo spazio in cui il router mostra la
  schermata corrente; la pagina ha `lang="it"` e titolo "maies".
- I test Vitest coprono: il reindirizzamento di `/` e di un indirizzo
  sconosciuto a `/esercizi`, e la resa del titolo di ciascuna delle quattro
  schermate al suo indirizzo. `npm test`, `npm run typecheck` e
  `npm run build` riescono.
- Nessun test in un browser reale; nessun ESLint, Prettier o libreria di
  componenti o CSS.

## Decisions
- **npm come gestore di pacchetti**, con `package-lock.json` versionato: la
  Action del task 4 installa con `npm ci` dallo stesso lockfile.
- **Schermate in `src/views/`, router in `src/router/index.ts`, test in
  `tests/`**: il documento di feature non fissa i percorsi; il router è
  l'unico punto in cui le funzionalità successive registrano schermate e
  sottorotte.
- Il file `CNAME` alla radice del repository non viene toccato: con la
  pubblicazione tramite Action GitHub lo ignora, e il dominio si imposta
  nelle impostazioni Pages (task 4).
